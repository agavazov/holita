# Foundation requirements

These criteria describe the current workspace and local application foundation.
The contract includes persistence, schema-first Stores/Products APIs and their Refine admin.

| ID      | Requirement and acceptance criterion                                                                                                                                                                                                                            |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FND-001 | Exactly four applications exist: admin, gateway, core and products. npm run projects identifies all four.                                                                                                                                                       |
| FND-002 | npm workspaces and one package-lock.json manage dependencies. Nx provides project tasks and affected selection. No cloud account is required.                                                                                                                   |
| FND-003 | Root dev commands start host Node.js processes, together or independently, with readable application-prefixed group logs and clean shutdown.                                                                                                                    |
| FND-004 | Application listeners bind to loopback. Defaults are gateway 11080, admin 11081, core 11082 and products 11083. Backend PORT overrides must be valid TCP ports.                                                                                                 |
| FND-005 | Every backend exposes GET /health without database, store context or identity prerequisites; the response identifies its service and status.                                                                                                                    |
| FND-006 | Strict TypeScript, ESLint and formatting are shared consistently. Cross-application source imports are rejected, including relative imports.                                                                                                                    |
| FND-007 | Each application has explicit lint, typecheck, build and test tasks. Root named test commands support runner-native file/case selection without watch mode and show successful runner summaries through static Nx output.                                       |
| FND-008 | Missing test files must not silently broaden selection. Zero executed tests is not a passed behavioral check. No passWithNoTests configuration is allowed.                                                                                                      |
| FND-009 | Affected checks use an explicit meaningful Git comparison and account for shared configuration. Full regression is a separate manually selected command.                                                                                                        |
| FND-010 | Documentation describes the commands and limitations that exist. Contributor rules and focused validation guidance use real reference paths.                                                                                                                    |
| FND-011 | Compose contains only PostgreSQL, bound to loopback with a persistent volume. db:down/up preserves existing data.                                                                                                                                               |
| FND-012 | Core and products own separate development and test databases, credentials, Prisma schemas, migrations and generated clients. No application imports another's client or database model.                                                                        |
| FND-013 | Host provisioning and migrate deploy are explicit and repeatable, without reset, volume deletion, credential overwrite or database ownership reassignment.                                                                                                      |
| FND-014 | Store/Product persist UUIDs and timestamps; Product has DRAFT/ACTIVE status (default DRAFT), a case-sensitive unique (storeId, sku) constraint and store-scoped ordering index.                                                                                 |
| FND-015 | Seeds provide two stable stores and three distinct products each. Reruns preserve user rows, edits and SKU conflicts. Core seeds before products.                                                                                                               |
| FND-016 | Real PostgreSQL tests reject development/remote/elevated URLs, use unique schemas, clean up only their own schemas, and never reuse cached DB test results.                                                                                                     |
| FND-017 | Prisma clients are ignored generated output. Root checks/builds and independent core/products startup and seed scripts generate them without needing a live database.                                                                                           |
| FND-018 | Owned SDL is the API source of truth. Local composition, public-schema generation and named-operation validation work without services or databases.                                                                                                            |
| FND-019 | Backend argument/result types and client operation/variable/document types are generated. Dependent startup/build/check tasks regenerate or restore artifacts using explicit contract/tool inputs.                                                              |
| FND-020 | Gateway serves a static supergraph and forwards request/store headers without blanket existence checks. It can start while subgraphs are unavailable.                                                                                                           |
| FND-021 | Core lists and looks up stores without selected-store context. Unknown UUID lookup returns null; malformed UUIDs are rejected. Store federation references resolve from core persistence.                                                                       |
| FND-022 | All Products operations require a valid UUID store context. Repositories scope every read/write, and foreign product IDs return NOT_FOUND without changing rows.                                                                                                |
| FND-023 | Products CRUD trims name/SKU, counts Unicode code points against matching form/database limits, rejects NUL characters before persistence, enforces status/defaults, maps SKU conflicts and rejects store reassignment, empty updates and null update values.   |
| FND-024 | Product pagination returns items and matching total with offset/limit, defaults 0/20, limit 1..100, and deterministic createdAt/ID descending order. Optional trimmed search matches partial product names or SKUs case-insensitively and always remains store-scoped; blank search is unfiltered. |
| FND-025 | Creation validates the store through core before writing and reuses validation within a products HTTP request. Unknown stores and unavailable validation produce distinct errors with no insert.                                                                |
| FND-026 | A valid unknown store lists zero products. Product-only read/update/delete work without core; fields selecting Product.store use real gateway federation and depend on core.                                                                                    |
| FND-027 | Product entity references enforce active store scoping and ignore spoofed representation fields. Core/products never share database clients or implementation imports.                                                                                          |
| FND-028 | Request IDs propagate across the gateway and subgraphs, appear in responses/errors and support diagnostics. Concurrent requests cannot share mutable store context.                                                                                             |
| FND-029 | Expected GraphQL errors have consistent codes; unexpected messages/stacks are hidden from clients. Real HTTP/DB and whole-graph focused tests exercise these contracts with isolated resources.                                                                 |
| FND-030 | Admin lists stores without product context, keeps a header switcher, and uses reloadable store-scoped Products routes. Unavailable stores do not trigger product requests.                                                                                      |
| FND-031 | Products UI provides server pagination, debounced name/SKU search, create/edit through one ProductForm, confirmed delete, validation, pending guards, notifications and loading/empty/error/retry states. Search changes reset pagination to the first page. |
| FND-032 | One Refine GraphQL provider maps generated operations. Refine owns the cache; store identity is part of query resource keys, request headers and mutation invalidation. Components never fetch directly.                                                        |
| FND-033 | Store switching resets forms/navigation/pagination/search. Late requests, including searched lists, cannot show another store's rows; pending writes retain their initiating store and cannot redirect, notify or overwrite a new editor, including navigation between editors in the same store. |
| FND-034 | Focused component tests cover forms/provider/store switching. The explicit noncached Playwright target exercises real CRUD for both stores, delayed reads and pending writes using guarded temporary test schemas.                                              |
| FND-035 | PR CI installs with npm ci and checks affected lint/typecheck/build, unit/DB targets and admin browser smoke. Root-tool, format and offline schema checks run even when no application is affected.                                                             |
| FND-036 | CI uses the PR event base/head with full history; missing commits or common ancestry fail explicitly. Workflow/ignore changes affect all four apps. An empty application selection is reported without claiming application coverage.                           |
| FND-037 | Full regression CI has workflow_dispatch as its only trigger. Both workflows run Node on the host, provision PostgreSQL with existing root scripts, preserve volumes on shutdown and contain no deployment.                                                     |

Product identity is **holita** across UI, workspace packages, local resource names and
project skills. `red.bg` is the temporary service domain. Transitioning an existing
installation preserves credentials, stored rows and applied migration history; seeds
do not rename existing stores or overwrite user edits.

No authentication or authorization is provided. Store context scopes data in trusted local
development; a caller can select another store. A health response proves that its application is responding, not database
readiness or downstream service availability.
